## 一、结论速览

一句话：**搜题酱把"刷课"拆成了"扫描器 → 任务目录 → 单队列 → 分类型执行器 → 提交状态机"五段**，
真正值得借鉴的是这套分层和它的安全网，而不是某一批选择器。

它强在：

1. **不猜标签页**。先扫出本节的任务清单，再按清单逐项做，天然适配"学习要点 / 微课学习 / 拓展阅读"多标签结构。
2. **目录驱动**。任务类型由 URL 模块名映射到一张 `CX_TASK_CATALOG` 表，新增类型只改表。
3. **异步安全**。三字段路由指纹 + 扫描代际 + `routeEpoch`，页面切走后旧结果直接丢弃，不写回新页面。
4. **成绩优先**。测验用 `doneFlags` / `submitSafeFlags` 双数组，有题没把握就暂存而不是硬交。
5. **弹窗处理完整**。`#workpop` → `#popok` / `#popno` → `#workpopFocus`（及格线）都有分支。

它弱在：

1. **重云依赖**。解题走自家 `solveTask` 服务，题目上传（`SaveExcise` / `UploadAllQuestion`）、会员权益、AI 求解都在云端；断网或非会员基本只剩播放器。
2. **完成判定只看一个 class**。视频完成只认父容器 `.ans-job-finished` + `.ans-job-icon`，不读平台 `aria-label`，也不看课程树/`#_studystate`。
3. **没有平台限流/风控处理**。代码里没有"今日视频任务点已达上限"这类文案检测，也没有验证码分支（✅ 全文检索无命中）。
4. **选择器硬编码 id**。`#workpop`、`#popok`、`#popcontent`、`#panView`、`#prevNextFocusNext`——平台改版即失效。
5. **节奏是固定 sleep**。2s / 4s / 5s / 15s 常数，不是拟人化随机；高频场景全靠常数兜。

它 vs 我们（详表见第八节）：

| 维度 | 搜题酱 v1.17.5 | 我们 v1.3.0 |
|---|---|---|
| 任务发现 | 注入 MAIN world 扫描器扫 DOM ✅ | 顶层 content script 扫 d1 帧 ✅ |
| 类型识别 | URL 正则 + catalog ✅ | 原样移植 catalog ✅ |
| 顺序 | 单队列按 DOM 顺序 ✅ | 同左 ✅ |
| 完成判定 | 只读 `.ans-job-finished` ✅ | `aria-label` 优先，class 兜底 ✅ |
| 路由一致 | 指纹 + 代际 ✅ | 三字段指纹 + 代际 ✅ |
| 测验提交 | flags 安全网 + 暂存 ✅ | 同思路（`workSafe` + `doTmpSave`）✅ |
| 解题来源 | 自家云服务 + 会员 ✅ | 用户自配 OpenAI 兼容 API + 截图兜底 ✅ |
| 倍速 | 读配置 rate，循环重设；自建课程强制 1x ✅ | 设一次 + 回读验证，被拒就放弃 ✅ |
| 限流/验证码 | 无 ✅ | 检测到每日上限主动停止 ✅ |

## 三、任务目录与类型识别

### 3.1 任务目录（原样照抄）

`CX_TASK_CATALOG`（模块 `3oCgF`）✅：

| 类型 | `helper` | `queueDrained` | `rawTypes` | 含义 |
|---|---|---|---|---|
| `video` | `video` | `default` | `["video"]` | 视频 |
| `audio` | `video` | `default` | `["audio"]` | 音频 |
| `pdf` | `video` | `default` | `["pdf"]` | PDF |
| `work` | `exam` | `default` | `["work"]` | 章节测验 |
| `pack` | `exam` | `default` | `["pack"]` | 作业包（展开后的任务） |
| `bbsReply` | `exam` | `none` | `[]` | 讨论回复 |
| `bbsTopic` | `exam` | `default` | `[]` | 讨论主题 |
| `bbsTopicList` | `exam` | `default` | `[]` | 讨论列表 |
| `text` | `video` | `text` | `[]` | 纯图文 |

- `helper` 决定交给哪个执行器族：`video` 族（播放器/滚动）或 `exam` 族（答题）。
- `queueDrained` 决定队列做空后怎么办：`default` → 走自动翻页；`text` → 走图文专用翻页（先滚到底再点下一节）；`none` → 什么都不做。
- `rawTypes` 是"URL 模块名 → 本类型"的白名单；bbs/text 系没有 URL 白名单，只能由扫描器按 DOM 特征直接给 `source`。

### 3.2 类型提取

```js
// 模块 3oCgF，去压缩变量名后的等价逻辑 ✅
const extractCxRawTaskType = (src = "") => {
  let path = src;
  try { path = new URL(src, location.href).pathname; } catch {}
  const m = path.match(/\/ananas\/modules\/([^/?#]+)/);
  if (m) return m[1].toLowerCase();
  return path.includes("/ananas/dialog/ballchart") ? "ballchart" : "";
};
```

规则表：

| 输入 | 输出 rawType | 后续 |
|---|---|---|
| `/mooc-ans/ananas/modules/video/index.html?...` | `video` | → catalog `video` |
| `/ananas/modules/work/index.html` | `work` | → catalog `work` |
| `/ananas/modules/zt/topicAttachment/...` | `zt` | 扫描器判"展开"后改成 `pack` |
| `/ananas/modules/insertbbs/...` | `insertbbs` | 扫描器从列表里剔除 |
| `/ananas/dialog/ballchart` | `ballchart` | catalog 无此类型 → 不支持 |
| 其它模块名 | 原样小写 | 可能 `unknown` |

`resolveCxTaskType(raw)` 遍历 catalog 的 `rawTypes` 找第一命中；`getCxTaskMeta(type)` 取回 `helper`/`queueDrained`。

### 3.3 规范化与兜底

`normalizeTasks(list)`（模块 `fOAW0`）✅：

| 扫描结果 `source` | 规范化后 `type` | 依据 |
|---|---|---|
| `bbs` | `bbsReply` | 直接映射 |
| `bbsTopic` | `bbsTopic` | 直接映射 |
| `bbsTopicList` | `bbsTopicList` | 直接映射 |
| `pack` | `pack` | 直接映射 |
| `blockquote` | `work`（再走 extract） | 折叠块里的任务默认按测验 |
| `iframe` | `extractCxRawTaskType(src)` → `resolveCxTaskType`；解析不出则 `unknown` | URL 模块名 |

- 输入会先过滤：只接受 `iframe` / `blockquote` / `pack` / `bbs` / `bbsTopic` / `bbsTopicList` 六种 `source`，且 `id` 为字符串、`order` 为数字。
- **一条任务都没有时**，兜底造一条 `text`：

```js
// 模块 fOAW0 ✅
{ id: `text-${window.location.href || "unknown"}`, type: "text", source: "page", order: 0, src: href }
```

这条兜底保证了"看不到任务也要能翻页"，也解释了为什么纯图文章节不会卡死。

### 4.2 三个指纹

```js
// brushCx：路由指纹 p()、比较 d()、完整指纹串 f() ✅
const p = () => ({
  href: location.href,
  mainIframeSrc: iframeEl?.src || "",
  mainDocumentHref: iframeEl?.contentWindow?.location?.href
                  || iframeEl?.contentDocument?.URL || ""
});
const d = (a, b) => a.href === b.href
  && a.mainIframeSrc === b.mainIframeSrc
  && a.mainDocumentHref === b.mainDocumentHref;
const f = () => JSON.stringify({
  topHref: location.href,
  iframeSrc: iframeEl?.src || "",
  iframeDocUrl: iframeEl?.contentDocument?.URL || "",
  iframeLocationHref: iframeEl?.contentWindow?.location?.href || ""
});
```

| 函数 | 字段 | 用途 |
|---|---|---|
| `p()` | 3 字段（href / iframe src / iframe 文档 URL） | 判断"路由是否真的变了" |
| `d(a,b)` | 同上 | 三字段全等才算同路由 ✅ |
| `f()` | 4 字段（多一个 iframe 的 `location.href`） | 序列化后做**去重**：与上次扫描指纹相同就 `skipScan` |

### 4.3 扫描流程

| 步 | 动作 | 超时/兜底 |
|---|---|---|
| 1 | 任一事件触发 `x(reason)` → `version++`，清掉旧 timer，500 ms 后再扫 | 去抖 500 ms ✅ |
| 2 | `m(token)` 等顶层 `document.readyState === "complete"` | 15 s；过期直接放弃 |
| 3 | `g(token)` 等 d1 `#iframe` 的 `readyState === "complete"`，且文档 URL / location 都不是 `about:blank` | 15 s；超时打 `[brushCx][waitIframeTimeout]` |
| 4 | 读 `#iframe`.contentDocument；`E(doc)` 扫 `iframe, .blockquote-wrap` | 无 doc 返回 `[]` |
| 5 | `I(doc)` / `A(doc)` 判 bbs 讨论 / 讨论列表 | 命中则作为任务追加到队尾 |
| 6 | 过滤 `insertbbs` 的 iframe（它由 bbs 任务单独处理） | — |
| 7 | 扫完回头校验：`version`、`scanToken`、`route` 三者任一变化 → `[brushCx][discardScan]`，不发送 | ✅ **三重**校验 |
| 8 | `postMessage` 发送 `{ route, tasks }`，再挂 `MutationObserver` | — |
| 9 | `v()` 监听 `#prev_tab` 存在时 d1 iframe 的 `src` 属性变化 → `x("iframe_src_mutation")` | 需要 `#prev_tab` 有 `li` |
| 10 | hook `history.pushState` / `replaceState` + `popstate` + **每 1 s** 轮询 `f()` | 处理 SPA 变化 |

> **材料/代码差异**：任务说明里写"version/route 双重校验"，代码实际是
> `version`、`scanToken`、`route` **三重**（✅ 直读）。文档按代码写。

## 十、风险与合规提醒

| 风险 | 说明 | 建议 |
|---|---|---|
| 逆向的边界 | 本文只做**静态阅读**，目的是学架构；不复制代码、不搬运资源、不发布解包产物 | 引用时注明出处与用途 |
| 平台风控 | 高频轮询、固定节奏、异常 UA 都可能触发风控；搜题酱自己也只是"固定 sleep"，没有拟人化 | 我们保留 2.5 s 主循环，不加高频重试 |
| 每日限流 | 平台达到上限后不再累计任务点，继续刷是浪费时间与账号风险 | 我们检测到「今日视频任务点已达上限」就停止 |
| 云端数据 | 搜题酱会把题目上传自家服务器；我们坚持只发用户自配 API | 不引入任何第三方上传 |
| 学习通条款 | 页面明确提示"严惩刷课等作弊行为" | 仅技术学习；使用后果自负 |
| 账号安全 | 自动化操作可能触发验证码/异常登录 | 触发即停，不尝试绕过 |

> **结论**：值得学的是"先清点、再排队、按类型执行、提交留安全网、异步带代际"这套结构；
> 不值得学的是"把关键能力绑在自家云服务上"和"用一个 class 判断任务点完成"。
