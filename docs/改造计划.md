## 三、根因分析

| 环节 | 现有代码 | 问题 |
|------|---------|------|
| 视频完成判断 | 只看 `v.paused` | 只要在播就 next，不看进度 |
| 视频时长读取 | 直接读 `v.duration` | 初始是 `null`，直接被判成"无法判断"跳过 |
| 题目检测 | `hasQuiz()` 查 `.questionLi` | 真实容器是 `.TiMu`，永远查不到 |
| 题目作用域 | 在顶层查 | 题目在 `doHomeWorkNew` 帧（d3） |
| 任务点校验 | 只看 `.icon_Completed` | 漏掉 `#jobhint` 和当前树节点 |
| 翻页时机 | `docDone = true` 就翻 | 没校验任务点是否真完成 |

**一句话总结**：所有"完成"判断都基于 `if (元素存在)`，没有基于**真实完成度**，所以滚完就跑。

## 四、改造方案

### 4.1 视频任务点（优先级 P0）

**新增 `checkVideoTask()`**：

```js
/**
 * 返回 { state, currentTime, duration, percent, needContinue }
 *   state: 'no-video' | 'loading' | 'playing' | 'done'
 *   needContinue: true 表示还不能翻页
 */
async function checkVideoTask() {
  const v = q1('video');
  if (!v) return { state: 'no-video', needContinue: false };

  // 1. 没元数据 → 先播起来
  if (!isFinite(v.duration) || v.duration <= 0) {
    if (v.paused) { try { await v.play(); } catch {} }
    // 等 loadedmetadata（最多 8 秒）
    await waitFor(() => isFinite(v.duration) && v.duration > 0, 8000);
  }

  // 2. 还是没时长 → 判为加载中，继续等
  if (!isFinite(v.duration) || v.duration <= 0) {
    return { state: 'loading', needContinue: true };
  }

  // 3. 算进度
  const percent = v.currentTime / v.duration;
  const done = percent >= state.cfg.auto.videoThreshold;  // 默认 0.9

  return {
    state: done ? 'done' : 'playing',
    currentTime: v.currentTime,
    duration: v.duration,
    percent,
    needContinue: !done
  };
}
```

**改动点**：
- `runVideo()` 末尾加：`state.videoDone = (percent >= 0.9)`
- `tick()` 里：`videoDone === false` 时**直接 return，不往下走翻页**

**新增配置**：

```js
auto: {
  videoThreshold: 0.9,     // 视频完成度门槛（0.9 = 90%）
  videoWaitTimeout: 300,   // 视频最长等待秒数（防止死等）
}
```

**新增 `scrapeQuiz()`（重写）**：

```js
/**
 * 抓取题目，返回：
 * [{ num, type, qtype, qid, title, options: [{letter, text}], inputs }]
 */
async function scrapeQuiz() {
  const qs = qAll('.TiMu');
  return qs.map((q, i) => {
    const typeEl = q.querySelector('.newZy_TItle');
    const typeText = (typeEl?.innerText || '').trim();

    // 题型判定（优先看 qtype 属性，比文字可靠）
    const firstLi = q.querySelector('.Zy_ulTop li');
    const qtype = firstLi?.getAttribute('qtype') ?? '';
    const kind =
      qtype === '1' ? 'multi' :
      qtype === '3' ? 'judge' :
      qtype === '0' ? 'single' :
      /多选/.test(typeText) ? 'multi' :
      /判断/.test(typeText) ? 'judge' :
      /填空/.test(typeText) ? 'fill' : 'single';

    // 题干
    const titleEl = q.querySelector('.Zy_TItle .font-cxsecret') || q.querySelector('.Zy_TItle');
    const title = (titleEl?.innerText || '').replace(/\s+/g, ' ').trim();

    // 选项（注意：多选和单选/判断的 span class 不同）
    const spanSel = kind === 'multi' ? '.num_option_dx' : '.num_option';
    const options = [...q.querySelectorAll('.Zy_ulTop li')].map(li => ({
      // data 值：选择题是 A/B/C/D，判断题是 "true"/"false"
      value: li.querySelector(spanSel)?.getAttribute('data') || '',
      letter: (li.querySelector(spanSel)?.innerText || '').trim(),
      text: (li.querySelector('a.after')?.innerText || '').replace(/\s+/g, ' ').trim(),
      qid: li.getAttribute('qid'),
      onclick: li.getAttribute('onclick'),
      checked: !!(li.querySelector(spanSel)?.className || '').match(/check_answer/)
    }));

    // 填空题的 textarea（UEditor 用，不是 input[type=text]）
    const fillAreas = [...q.querySelectorAll('textarea[name^=answerEditor]')];

    return {
      index: i + 1,
      num: q.getAttribute('data'),
      type: kind,
      qtype,
      qid: firstLi?.getAttribute('qid') || q.querySelector('input[id^=answertype]')?.id?.replace('answertype','') || '',
      title,
      options,
      fillAreas,
      el: q                                  // 保留 DOM 引用，填充时用
    };
  });
}
```

### 4.4 自动答题（优先级 P1）

**流程**：

```
scrapeQuiz()
  ↓
字体解码
  ↓
判断可信度（解码率 + 生僻字比例）
  ├─ 可信 → callAnswerApi(text)  → 解析答案
  └─ 不可信 → callVisionApi(截图) → 解析答案
  ↓
fillAnswers(answers)   ← 按题型分别填充
  ↓
（默认）不提交，等用户确认
  ↓
（可选）autoSubmit = true → 点 btnSubmit
```

**填充逻辑（按实测结构，三种题型分开处理）**：

```js
function fillAnswers(answers, questions) {
  for (const ans of answers) {
    const q = questions.find(x => x.index === ans.num);
    if (!q) continue;

    // ---- 填空题：UEditor textarea ----
    if (q.type === 'fill') {
      const tas = q.el.querySelectorAll('textarea[name^=answerEditor]');
      ans.answer.forEach((val, i) => {
        const ta = tas[i];
        if (!ta) return;
        ta.value = val;
        ta.dispatchEvent(new Event('input', { bubbles: true }));
        ta.dispatchEvent(new Event('change', { bubbles: true }));
      });
      continue;
    }

    // ---- 选择题 / 判断题：点 li ----
    // 注意 span 的 class 不同：
    //   多选 → num_option_dx
    //   单选/判断 → num_option
    const spanSel = q.type === 'multi' ? 'span.num_option_dx' : 'span.num_option';

    for (const letter of ans.answer) {
      // 判断题的 data 是 "true"/"false"，需要转换
      const want = q.type === 'judge'
        ? String(letter).toLowerCase()            // 'true' / 'false'
        : String(letter).toUpperCase();           // 'A' / 'B'

      const li = [...q.el.querySelectorAll('.Zy_ulTop li')].find(x => {
        const span = x.querySelector(spanSel);
        return span && span.getAttribute('data') === want;
      });

      if (li) li.click();     // 触发 addChoice / addMultipleChoice
    }
  }
}
```

**关键注意点**：

1. **必须用 `.click()`**，不能直接改 DOM —— 否则 `answer<qid>` 隐藏域不更新，提交会报"未作答"
2. **多选题可取消**：点两次会切回未选中，填充前先检查是否已选中
3. **单选题互斥**：点新选项自动取消旧的，不需要手动清
4. **判断题 `data="true"/"false"`**，API 返回的"对/错"要先转成布尔字符串
5. **填空题 textarea 写值后要触发 `input` + `change` 事件**

### 4.5 任务点完成校验（优先级 P0）

**新增 `isChapterReallyDone()`**（用实测确认的四级信号）：

```js
/**
 * 四级校验，全部通过才算完成
 *
 * 数据来源（全部实测确认，见 §11.4 / §11.6）：
 *   ① #_studystate     学习通自己维护的全局状态（最可靠）
 *   ② 当前树节点       .icon_Completed / .jobUnfinishCount
 *   ③ #jobhint         本节课待完成计数
 *   ④ 视频实时进度      currentTime / duration
 */
function isChapterReallyDone() {
  // ── ① 全局状态（学习通自己写的，最权威）──
  try {
    const st = document.getElementById('_studystate');
    if (st && st.value) {
      // 注意：value 是伪 JSON（键无引号），要手动解析
      const mChapter = st.value.match(/nextChapterId\s*:\s*(\d+)/);
      const mUnfinish = st.value.match(/unfinishCount\s*:\s*(\d+)/);
      const unfinish = mUnfinish ? +mUnfinish[1] : null;
      const nextChapter = mChapter ? mChapter[1] : null;
      if (unfinish === 0) {
        return { done: true, allCourseDone: true };
      }
      // nextChapterId 指向别的章节 → 当前节已完成，该跳了
      const curChapter = (location.href.match(/chapterId=(\d+)/) || [])[1];
      if (nextChapter && curChapter && nextChapter !== curChapter) {
        // 还要看本节点是否标记完成
        // （平台会自动把 nextChapterId 指向下一个未完成的）
      }
    }
  } catch { /* ignore */ }

  // ── ② 当前树节点 ──
  const cur = document.querySelector('.posCatalog_select.posCatalog_active')
           || document.querySelector('.posCatalog_select[class*=current]');
  if (cur) {
    const isDone = !!cur.querySelector('.icon_Completed');
    const todoCnt = +(cur.querySelector('.jobUnfinishCount')?.value || 0);
    if (!isDone || todoCnt > 0) {
      return {
        done: false,
        reason: '当前节点待完成 ' + todoCnt + ' 个',
        todoCount: todoCnt
      };
    }
  }

  // ── ③ 本节课计数 ──
  const jh = document.getElementById('jobhint');
  const jhNum = jh ? parseInt((jh.textContent || '').trim(), 10) : 0;
  if (jhNum > 0) {
    return { done: false, reason: '本节还有 ' + jhNum + ' 个任务点' };
  }

  // ── ④ 视频实时进度 ──
  const v = q1('video');
  if (v && isFinite(v.duration) && v.duration > 0) {
    const pct = v.currentTime / v.duration;
    if (pct < state.cfg.auto.videoThreshold) {
      return {
        done: false,
        reason: '视频仅完成 ' + Math.round(pct * 100) + '%',
        videoPercent: pct
      };
    }
  }

  return { done: true };
}
```

**关于 `#_studystate` 的解析**：

实测 value 是 `{nextChapterId:1210130560,unfinishCount:93}` —— **键没引号，不是合法 JSON**，不能用 `JSON.parse`，要正则提取。

**改动 `tickTop()` 翻页逻辑**：

### 11.7 三种题型的精确差异（已补采确认）

**这是本次补采最重要的发现：三种题型的选择器不一样！**

| 题型 | `li` class | `span` class | `onclick` | `role` | 答案值 |
|------|-----------|--------------|-----------|--------|--------|
| 多选题 | `before-after-checkbox` | `num_option_dx choice<qid>` | `addMultipleChoice(this)` | `checkbox` | `"AB"` |
| 单选题 | `font-cxsecret before-after` | `num_option choice<qid>` | `addChoice(this)` | `radio` | `"B"` |
| 判断题 | `font-cxsecret before-after` | `num_option choice<qid>` | `addChoice(this)` | `radio` | `"true"/"false"` |

**关键点**：

1. **多选题用 `num_option_dx`，单选/判断题用 `num_option`** —— 不能共用一个选择器
2. **判断题的 `data` 属性是 `"true"` / `"false"`**，不是 A/B：
   ```html
   <span class="num_option choice405881812 check_answer" name="answer405881812" data="true">A</span>
   <span class="num_option choice405881812" name="answer405881812" data="false">B</span>
   ```
   选项文字是「对 / 错」
3. **选中状态用 `.check_answer` / `.check_answer_dx`** 标记
4. **多选题可以取消**（点两次恢复），实测：
   ```
   清空后: ""
   只选A:  "A"
   再选B:  "AB"
   选ACD:  "ACD"
   ```
5. **单选题互斥**，点新选项自动取消旧的

### 11.8 填空题：用 UEditor 富文本，不是普通 input

**这是个坑**——填空题没有 `input[type=text]`，用的是 UEditor：

```html
<div class="blankItemDiv">
  <span class="font14 tiankong">第1空：</span>
  <div class="XztiHover1 fl blankItemInp">
    <div id="inpDiv4058818081" class="InpDIV" style="display:none;"></div>
    <div class="textDIV">
      <div class="edui-editor edui-default" id="edui7">
        <div id="edui7_toolbarbox">...</div>
        <div id="edui7_iframeholder">
          <iframe id="ueditor_0" ...></iframe>
        </div>
      </div>
    </div>
  </div>
</div>
<!-- 答案实际存这里 -->
<textarea name="answerEditor4058818081" id="answerEditor4058818081" style="display:none;"></textarea>
<input type="hidden" name="tiankongsize405881808" value="1">
<input type="hidden" id="answertype405881808" value="2">
```

**实测结论**：

| 项 | 值 |
|----|-----|
| 全局 `window.UE` | **不存在**（`hasUEditorGlobal: false`） |
| 直接写 `textarea.value` | **可以写进去**（实测 `"测试答案"` 写入成功） |
| 每空对应 | 1 个 `textarea[name^=answerEditor]` |
| 空数标记 | `input[name^=tiankongsize]` 的 value |

**填充策略**：直接设置 `<textarea name="answerEditor<qid><空号>">.value`，然后触发 `input` / `change` 事件。因为 `window.UE` 不存在，走不了官方 API。

## 十四、v1.2.0 最终修复（实测驱动的迭代）

> 本节记录上线测试后，根据真实页面反馈继续修复的内容。

### 14.1 第一个问题：「需手动处理」死锁

**用户反馈**：面板显示「⏳ 任务点待完成 1 个，需手动处理」，一直卡住。

**根因**：两条规则冲突

| 规则 | 来源 | 后果 |
|------|------|------|
| 不自动切标签 | 用户之前的要求 | 扩展不会去「微课学习」 |
| 任务点不完成不翻页 | 用户的要求 | 扩展不敢跳过 |

叠加后：既不能去做，也不敢跳过，只能干等。

**额外问题**：重写代码时把 `skipUnfinished`（跳过未完成）配置**漏掉了**，连退路都断了。

**修复**：恢复 `skipUnfinished`，并把情况分四类：

```
A. 视频未达标      → 原地等，继续播
B. 题目没做        → 原地等，去做题
C. 文档没滚完      → 原地等，继续滚
D. 本页干不了活
   ├─ skipUnfinished=true  → 跳过并说明去了哪
   └─ skipUnfinished=false → 停下并明确告诉用户在哪个标签
```

### 14.2 方案 B：自动切到任务点标签

**用户决定**：选 B —— 任务点在别的标签时，自动切过去做完再翻页。

**实现**：

```js
// 新增 6 个函数
listChapterTabs()        // 列出章节内所有标签
activeChapterTab()       // 当前激活的标签
isContentTab(title)      // 是否内容型（排除学习要点/小结/书目）
switchToTab(tab)         // 切换标签
findNextContentTab()     // 找下一个内容型标签
currentTabContentDone()  // 当前标签内容是否做完
```

**接入 tickTop 的判断顺序**：

```
① 当前是纯文字标签，别处有内容型 → 切过去
② 当前内容型已做完，别处还有     → 切过去
③ 当前内容型没做完              → 原地等，别切走
④ 所有内容型都做完              → 检查任务点，过了就翻页
```

### 14.3 第二个问题：视频绿了但检测不到（核心 bug）

**用户反馈**：截图显示任务点已标绿，但脚本没检测到。

实测数据：

```
视频进度：1:28 / 7:53 = 18%
平台标记：任务点已完成（绿）
```

**根因有两个**：

**① 用错了判断依据**

原代码：
```js
currentTime / duration >= 0.9   // 18% < 90% → 判定未完成
```

平台真实标记（我之前完全没读）：
```html
<!-- 已完成 -->
<div class="ans-attach-ct videoContainer ans-job-finished">
  <div class="ans-job-icon ans-job-video ans-job-icon-clear"
       aria-label="任务点已完成">

<!-- 未完成 -->
<div class="ans-job-icon" aria-label="任务点未完成"></div>
```

**② 平台有每日限流**

页面里藏着（当时隐藏）：

```
今日视频任务点完成数已达上限，您可以观看视频，但无法完成任务点
今日视频观看时长已达上限，您可继续观看视频，但无法完成任务点
```

达到上限后，平台不再累计任务点，**直接标成完成**。这就是"才播 18% 就绿了"的原因。

**修复**：

```js
/**
 * 读平台的任务点完成标记（优先 aria-label）
 */
function readVideoTaskState() {
  // ① aria-label 最直接
  for (const el of qAll('[class*="ans-job-icon"]')) {
    const aria = el.getAttribute('aria-label') || '';
    if (/任务点已完成/.test(aria)) return { done: true, source: 'aria-label' };
  }
  // ② 容器 class
  if (qAll('.ans-job-finished').length) return { done: true, source: 'ans-job-finished' };
  // ③ 明确未完成
  // ④ class 推断
  return null;
}

/**
 * 检测每日限流
 */
function detectDailyLimit() {
  const txt = document.body?.innerText || '';
  if (/今日视频任务点完成数已达上限|今日视频观看时长已达上限/.test(txt)) {
    return { limited: true, reason: '今日视频任务点已达上限' };
  }
  return { limited: false };
}
```

**判断顺序改为**：

```
① 读平台标记（aria-label / ans-job-finished）  ← 主
② 有标记且已完成 → done
③ 有标记但未完成 → 未完成
④ 没有标记 → 才退回用进度算                   ← 兜底
```

**限流命中时主动停止**，避免白刷和风控：

```
⏸ 今日视频任务点已达上限，今天无法再完成任务点。已停止
```
