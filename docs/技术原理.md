本文讲清楚三件事：扩展怎么跑起来、刷课怎么实现、字体反爬怎么破。

### 为什么每个 frame 都注入一份

`manifest.json` 里 `content_scripts.all_frames = true`，每个 iframe 都会跑一份 `inject.js`。

**这是必须的** —— 题目在第四层 iframe 里，从顶层跨域查 DOM 会遇到问题；而且各框架的滚动容器、视频元素都只在自己文档里能操作。

### 怎么避免重复执行

如果每份实例都去抢视频、抢答题、抢翻页，会打架。所以采用**就近处理**原则：

| 职责 | 谁做 |
|---|---|
| 视频 / 文档 / 测验 | 自己文档里有，就自己处理 |
| 「下一节」翻页 | **只有顶层** |
| 悬浮面板 | **只有顶层** |

顶层翻页前会向后台问一句「还有别的 frame 在忙吗」，确认都闲下来才翻页，避免在视频还在播时就跳走。

### 状态汇总

每个 frame 通过 `frame:status` 消息上报自己的状态，后台按 `tabId + frameId` 存一份，面板显示最新最忙的那条。

## 二、刷课实现

### 视频

```js
v.muted = true;
v.playbackRate = 倍速;
v.play();
```

要点：

- **videojs 兼容**：优先调 `player.playbackRate()`，没有就设 `v.playbackRate`
- **持续纠正**：很多播放器每秒把倍速偷偷改回 1x，所以主循环每轮都检查一遍
- **防切屏暂停**：拦截 `visibilitychange` / `blur` / `mouseleave`，并改写 `document.hidden`

```js
doc.addEventListener('visibilitychange', e => e.stopImmediatePropagation(), true);
Object.defineProperty(doc, 'hidden', { get: () => false });
```

### 任务点完成检测（v1.2.0 新增）

这是刷课的核心：**必须先确认任务点真的完成，才能翻页。**

#### 四级校验

代码里 `isCurrentChapterDone()` 按顺序检查：

```js
① #_studystate        学习通自己维护的全局状态（最权威）
② 当前树节点           .icon_Completed / .jobUnfinishCount
③ #jobhint            本节课待完成计数
④ 视频任务点标记       aria-label="任务点已完成"
```

#### ① `#_studystate`（最可靠）

页面里藏着一个学习通自己的状态：

```html
<input type="hidden" id="_studystate"
       value="{nextChapterId:1210130560,unfinishCount:93}">
```

| 字段 | 含义 |
|------|------|
| `nextChapterId` | 平台认为下一个该学的章节 |
| `unfinishCount` | 整个课程未完成总数 |

⚠️ 注意：value 是**伪 JSON**（键没引号），`JSON.parse` 会报错，必须正则提取。

#### ② 课程树节点

```html
<div class="posCatalog_select posCatalog_active" id="cur1210130560">
  <span class="posCatalog_name">三、毛泽东思想的历史地位（微课）</span>
  <input type="hidden" class="jobUnfinishCount" value="1">   ← 待完成数
  <span class="catalog_points_yi">1个待完成任务点</span>     ← 未完成标记
  <!-- 或 -->
  <span class="icon_Completed">已完成</span>                ← 已完成标记
</div>
```

#### ③ `#jobhint`

```html
<a id="jobhint" class="jobhint" style="display:none;">0</a>
```

`0` = 本节无待完成任务点。

#### ④ 视频任务点标记（关键修复）

**踩过的坑**：视频才播到 18%，平台已经标绿了。

原因：**学习通有每日限流**

```
今日视频任务点完成数已达上限，您可以观看视频，但无法完成任务点
今日视频观看时长已达上限，您可继续观看视频，但无法完成任务点
```

达到上限后平台不再累计，直接标完成。

**所以不能用进度判断，必须读平台标记**：

```html
<!-- 已完成 -->
<div class="ans-attach-ct videoContainer ans-job-finished">
  <div class="ans-job-icon ans-job-video ans-job-icon-clear"
       aria-label="任务点已完成">

<!-- 未完成 -->
<div class="ans-job-icon" aria-label="任务点未完成"></div>
```

读取优先级：

```js
function readVideoTaskState() {
  // ① aria-label 最直接
  for (const el of qAll('[class*="ans-job-icon"]')) {
    const aria = el.getAttribute('aria-label') || '';
    if (/任务点已完成/.test(aria)) return { done: true, source: 'aria-label' };
  }
  // ② 容器 class
  if (qAll('.ans-job-finished').length) return { done: true, source: 'ans-job-finished' };
  // ③ 明确未完成
  // ④ class 推断
  return null;   // 本页没有视频任务点
}
```

**进度判断降为兜底**，只在没有任何平台标记时才用。

### 章节内标签切换（v1.2.0 新增）

学习通一个章节常有多个标签：

```
1学习要点    ← 纯文字说明，不是任务点
2微课学习    ← 真正的视频/文档任务点在这里
3拓展阅读
```

#### 切换策略（用户选的方案 B）

**任务点在别的标签时，自动切过去做完再翻页。**

```
① 当前是纯文字标签，别处有内容型 → 切过去
② 当前内容型已做完，别处还有     → 切过去
③ 当前内容型没做完              → 原地等，别切走
④ 所有内容型都做完              → 检查任务点，过了就翻页
```

### 正确答案填充（v1.2.0 新增）

#### 三种题型选择器不同（重要）

| 题型 | `li` class | `span` class | `data` 值 |
|------|-----------|--------------|-----------|
| 多选题 | `before-after-checkbox` | `num_option_dx` | `A/B/C/D` |

**不能共用一个选择器**。

#### 点击行为（实测）

```
多选题：点一次选中，再点一次取消   → 可累积（AB / ACD）
单选题：互斥，点新的自动取消旧的
判断题：和单选一样，点两次也会取消
```

**关键**：判断题点两次会取消！所以填充前必须**先清空所有已选中项**，再点目标。

```js
// 先清空
for (const o of q.options) {
  if (o.checked) { o.el.click(); await sleep(80); }
}
// 再点目标
for (const want of wants) {
  const target = q.options.find(o => o.value === want || o.letter === want);
  target.el.click();
  await sleep(100);
}
```

#### 必须用 `.click()`

不能直接改 DOM，否则 `answer<qid>` 隐藏域不更新，提交时会报「未作答」。

## 三、字体反爬（核心）

### 问题

学习通对题干做了**字体混淆**。看这个例子：

```html
<p>忞忖忟命応首要忚忝忛？</p>
```

```css
@font-face {
  font-family: "puzzle-font";
  src: url("/font/xxx.ttf");
}
p { font-family: "puzzle-font"; }
```

页面上人眼看到的是「中国革命的首要问题是？」，但 `innerText` 拿到的是「忞忖忟命応首要忚忝忛？」。

**拿去问模型，模型会答非所问。**

### 破解步骤

```
① 抓 @font-face
   ↓
② 下载字体文件
   ↓
③ FontFace 注册，用它渲染混淆字符 → 位图
   ↓
④ 认出这个字体派生自哪款系统字体
   ↓
⑤ 用同源系统字体渲染候选字 → 位图
   ↓
⑥ 逐像素比对，取最相似的字
```

### 关键步骤：认出派生字体

这是决定成败的一步。

**实测数据**（同一批汉字，不同字体渲染）：

| 对比 | 余弦相似度 |
|---|---|
| 同字体渲染同一个字 | **1.0000** |
| SimHei vs 微软雅黑 | 0.4429 |
| SimHei vs SimSun | 0.7087 |
| 形近字「要」vs「耍」 | 0.941（SimHei） |
| 形近字「垄」vs「重」 | 0.867（SimHei） |

**跨字体差异（0.44）远大于形近字差异（0.94）**。

这意味着：如果随便挑个系统字体当参照，形近字会被字体差异淹没，必然混淆 —— 这正是早期版本把「要」认成「善」、「垄」认成「重」的原因。

**解决办法**：

反爬字体通常只改了「被混淆的那批码位」，其余字符原样保留。所以拿一批**绝不会被混淆的常用字**（的一是在不了有和…）分别用反爬字体和各个系统字体渲染，逐字比对：

- 派生字体 → 得分接近 1.0
- 其他字体 → 只有 0.4 左右

得分最高者即为基础字体。

```js
const PROBE_CHARS = '的一是在不了有和人这中大为上个国我以要他时来用们生到作地于出';

async function detectBaseFont(fontFam) {
  // 用反爬字体渲染探测字
  const mine = renderFeatures(fontFam, PROBE_CHARS.split(''));

  let best = null, bestScore = -1;
  for (const fam of pickSystemFonts()) {
    const ref = renderFeatures(fam, PROBE_CHARS.split(''));
    let sum = 0, n = 0;
    for (const [ch, v] of mine) {
      const rv = ref.get(ch);
      if (rv) { sum += cosine(v, rv); n++; }
    }
    const score = sum / n;
    if (score > bestScore) { bestScore = score; best = fam; }
  }
  return { family: best, score: bestScore, confident: bestScore > 0.90 };
}
```

### 字形特征提取

不是直接比对原始像素，而是先做**包围盒归一化**：

1. 找出墨迹的边界框
2. **保持宽高比**缩放到 28×28（不能拉伸！否则「问」的口字旁会被压扁，认成「门」）
3. 得到 784 维特征向量

```js
const scale = Math.max(bw, bh);       // 等比缩放
const padX = (scale - bw) / 2;        // 居中留白
const padY = (scale - bh) / 2;
```

> 踩过的坑：早期用「拉伸填满正方形」，结果「问」的口被压成了「门」。保持宽高比才对。

### 搜索策略

两级，兼顾速度和覆盖：

| 级别 | 字库 | 触发条件 |
|---|---|---|
| 一级 | ~2700 常用字（GB2312 一级 + 思政专业词汇） | 总是先跑 |
| 二级 | CJK 基本区 2 万字 | 一级得分低于阈值才跑，且限制批次 |

同源字体下，一级命中基本就是 1.0 分，直接采信；二级只在「字体被整体替换、认不出派生字体」时才用。

### 性能

批量渲染：所有字一次画到同一张画布（32 列网格），只 `getImageData` 一次，再切片。比逐字 `createCanvas` + `getImageData` 快约 30 倍。

实测：2700 字建库约 0.3 秒，单段文本解码约 0.5 秒。

## 四、截图解题

### 为什么不直接整屏截图

学习通是四层 iframe，整屏会把侧边栏、播放器、导航栏全截进来，视觉模型会被干扰。

### 做法

```
① 算出题目区域的精确矩形（getBoundingClientRect）
   ↓
② 后台 chrome.tabs.captureVisibleTab 截可见区域
   ↓
③ OffscreenCanvas 裁剪到该矩形
```

**踩坑**：`captureVisibleTab` 的第一个参数是 **windowId**，不是 tabId。传 tabId 会报 `No window with id: xxx`。

**踩坑**：Service Worker 里 `fetch(dataURL)` 不可靠，要手动 base64 解码成 `Uint8Array` 再建 Blob。

### 长题目分屏

题目比屏幕高时，裁剪会被自动收缩，导致漏题。所以：

```
截图 → 检查是否被裁剪 → 是则向下滚动一屏 → 再截
```

最多截 `maxShots` 张（默认 3），拼成一条消息里的多张图发给视觉模型。

### 降级方案

截图彻底不可用（后台休眠、页面不可见等）时，退回**把题目文字重绘成 canvas**。

虽然丢了原始排版，但视觉模型主要看文字内容，一样能解。这个降级路径在字体解码失败时特别有用 —— 因为解码后的文字已经是对的，重绘出来视觉模型能直接读懂。

## 五、脚本与模型的双向判断

用户要求「模型和脚本共同判断何时该用截图」。

### 脚本侧

```js
function assessTextReliability(scraped) {
  const reasons = [];

  // 1. 字体解码置信度低
  // 2. 题干过短
  // 3. 生僻字比例 > 15%（疑似还是乱码）
  // 4. 仍含已知混淆字符（忞忖忟命…）
  // 5. 单选/多选选项少于 2 个

  return { reliable: reasons.length === 0, reasons };
}
```

### 模型侧

视觉模型的提示词里强制要求每题返回 `confidence`：

```json
{
  "answers": [{ "num": 1, "answer": ["B"], "confidence": 1.0 }],
  "uncertain": false,
  "note": ""
}
```

`confidence < 0.6` 或 `uncertain: true` → 判定不可靠。

### 决策

```js
const wantVision = visionOn && (
  mode === 'always' ||        // 强制截图
  !assess.reliable            // 文本不可靠
);
```

### 安全设计

即使 `autoSubmit` 开着，只要视觉模型标了不确定，**仍然跳过提交**：

```js
const canSubmit = cfg.quiz.autoSubmit && !(visionMeta && visionMeta.uncertain);
```

理由：截图解题本来就比文本答题更容易出错，出错时自动交卷等于直接锁死分数。

## 七、已知限制

| 限制 | 说明 |
|---|---|
| 视频倍速上限 | 受浏览器限制，实际最高 16x，建议 ≤2.0 |
| 跨域 iframe | 非同源 iframe 无法穿透，此时该 frame 的功能不可用 |
| 字体认不出派生 | 退化为多字体投票 + 骨架归一化，精度下降 |
| 视觉模型必备图片能力 | `deepseek-chat` 这类纯文本模型不能用 |
| Service Worker 休眠 | MV3 特性，靠消息自动唤醒 |
| **每日任务点上限** | 学习通平台限制，非 bug。命中后扩展主动停止 |
| **提交确认弹窗** | 未真实验证，已加通用「确定/确认」兜底点击 |
| **填空题提交识别** | 直接写 `textarea.value`，需真实提交验证是否被采纳 |
| **子帧调度延迟** | 测验帧的循环依赖顶层广播，偶有 1-2 轮延迟 |

### 每日限流说明

学习通会按天限制任务点完成数：

```
今日视频任务点完成数已达上限，您可以观看视频，但无法完成任务点
今日视频观看时长已达上限，您可继续观看视频，但无法完成任务点
```
