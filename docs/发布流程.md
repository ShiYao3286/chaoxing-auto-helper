# 发布流程

本项目用 GitHub Actions 自动打包，**推送 tag 即发布**。不需要本地装 Node、不需要手动打 zip。

---

## 发新版只需两步

### 1. 改版本号

编辑 `extension/manifest.json`：

```json
{
  "version": "1.0.1"
}
```

> 版本号必须是 `主.次.修` 三段数字格式，工作流会校验，格式不对会构建失败。

### 2. 推 tag

```bash
git add extension/manifest.json
git commit -m "发布 v1.0.1"
git push

# 打 tag 并推送（tag 名要和版本号对应）
git tag -a v1.0.1 -m "v1.0.1"
git push origin v1.0.1
```

推送 tag 后，GitHub Actions 自动：

```
校验 manifest 字段
  ↓
检查引用的文件是否齐全
  ↓
检查所有 JS 语法
  ↓
打包成 zip（zip 根目录直接是 manifest.json）
  ↓
创建 Release 并附上 zip
```

一两分钟后刷新 [Releases](https://github.com/ShiYao3286/chaoxing-auto-helper/releases) 就能看到。

---

## 只打包不发布

想先看看打包结果，不想发 Release：

```
仓库页 → Actions → 左侧「打包发布」→ Run workflow → Run
```

跑完后在该次运行的页面底部 **Artifacts** 里能下载 zip，保留 90 天。

---

## 工作流做了什么校验

触发后会依次检查，任何一步失败都不会发布：

| 检查 | 内容 |
|---|---|
| manifest 字段 | 必须是 MV3、version 格式正确 |
| 引用完整性 | `icons`、`service_worker`、`default_popup`、`options_page`、`content_scripts` 里列的文件必须都存在 |
| JS 语法 | `extension/` 下所有 `.js` 过一遍 `node --check` |
| zip 结构 | 自检 zip 根目录下必须有 `manifest.json` |

## zip 的结构

**关键**：打包时 `cd extension` 再 `zip .`，所以 zip 根目录直接是 `manifest.json`：

```
chaoxing-auto-helper.zip
├── manifest.json      ← 根层
├── icons/
└── src/
```

用户解压后能直接选这个目录加载，不用再进一层。

这也是为什么**不要**用「下载源码 zip」的方式分发 —— GitHub 的源码 zip 会套一层 `chaoxing-auto-helper-main/`，里面还有 `extension/`，用户很容易选错层级。

## 排查构建失败

```
仓库页 → Actions → 点进失败的那次 → 展开红色步骤
```

常见问题：

| 现象 | 原因 |
|---|---|
| `找不到 extension/manifest.json` | 目录结构被改了 |
| `引用的文件不存在: xxx` | manifest 里写了但文件没提交 |
| `xxx 语法错误` | JS 有语法问题 |
| `zip 结构不对` | 打包命令被改动 |

本地可以先自查一遍：

```bash
# 语法
node --check extension/src/background.js

# manifest 引用（用项目里的测试脚本）
node tests/fontdecoder.test.cjs
```

## 回滚发布

Release 里的包已经发出去了，撤不回来。但可以：

**打补丁版**（推荐）

```bash
# 改版本号 1.0.2，修好问题，重新发
git tag -a v1.0.2 -m "v1.0.2 修复 xxx"
git push origin v1.0.2
```

**删除错误的 Release**

```
Releases → 点进那个版本 → Delete
```

对应的 tag 也要删：

```bash
git push --delete origin v1.0.1
git tag -d v1.0.1
```

## 关于 Chrome Web Store

如果以后想上架商店，这个 zip **不能直接提交** —— 商店要求：

- 单独的隐私政策页面（说明不收集数据）
- 更详细的商店描述和截图
- 可能需要调整权限说明

`<all_urls>` 权限在审核时会被重点问，需要准备好解释（截图解题需要访问任意页面）。

个人用的话，Release 下载 + 加载解压缩的扩展就够了。
