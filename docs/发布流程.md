# 发布流程

本项目用 GitHub Actions 自动打包，**推送 tag 即发布**。不需要本地装 Node、不需要手动打 zip。
**一次发布产出两个产物**：扩展 zip + 油猴 `.user.js`。

---

## 发新版只需两步

### 1. 改版本号

编辑 `extension/manifest.json`：

```json
{
  "version": "1.0.1"
}
```

> 版本号必须是 `主.次.修` 三段数字格式，工作流会校验，格式不对会构建失败。
> **油猴脚本的 `@version` 不需要手动改** —— 构建脚本从 manifest 读，自动同步。

### 2. 推 tag

```bash
git add -A
git commit -m "发布 v1.0.1"

# 打 tag 并推送（tag 名要和版本号对应）
git tag -a v1.0.1 -m "v1.0.1"
git push origin main
git push origin v1.0.1
```

推送 tag 后，GitHub Actions 自动：

```
校验 manifest 字段
  ↓
检查引用的文件是否齐全
  ↓
检查所有 JS 语法
  ↓
构建油猴脚本 + 4 项自检（头 / 版本一致 / 无 chrome.* 残留）
  ↓
打包扩展 zip（zip 根目录直接是 manifest.json）
  ↓
创建 Release，附上 zip 和 .user.js 两个文件
```

一两分钟后刷新 [Releases](https://github.com/ShiYao3286/chaoxing-auto-helper/releases) 就能看到。

## 只打包不发布

想先看看打包结果，不想发 Release：

```
仓库页 → Actions → 左侧「打包发布」→ Run workflow → Run
```

跑完后在该次运行的页面底部 **Artifacts** 里能下载，保留 90 天。产物包含：

```
chaoxing-auto-helper.zip
userscript/学习通自动学习助手.user.js
```

## 本地构建油猴脚本

不想等 CI，本地可以先产出并自查：

```bash
node build/build-userscript.cjs
```

产物：`userscript/学习通自动学习助手.user.js`（约 254 KB）

**构建脚本内置 5 项校验**，任何一项失败都不产物：

| # | 校验 | 为什么 |
|---|---|---|
| 1 | 除宿主外不得出现 `chrome.*` | 脚本里没有扩展 API，出现就是 bug |
| 2 | 头部必需项齐全（`@match`/`@grant`/`@connect`） | 少了脚本装不上或请求发不出 |
| 3 | 版本号与 manifest 同源 | 防止两处版本漂移 |
| 4 | UI 源码不得硬编码颜色 | 必须走 `CSTheme` 令牌，否则两界面会不一致 |
| 5 | 产物语法可解析 | 拼接出错要立刻发现 |

只想校验不写文件：

```bash
node build/build-userscript.cjs --check
```

---

## 工作流做了什么校验

触发后会依次检查，任何一步失败都不会发布：

| 检查 | 内容 |
|---|---|
| manifest 字段 | 必须是 MV3、version 格式正确 |
| 引用完整性 | `icons`、`service_worker`、`default_popup`、`options_page`、`content_scripts` 里列的文件必须都存在 |
| JS 语法 | `extension/` 下所有 `.js` 过一遍 `node --check` |
| 油猴产物 | 构建成功、`// ==UserScript==` 头存在、`@version` 与 manifest 一致、无 `chrome.*` 残留 |
| zip 结构 | 自检 zip 根目录下必须有 `manifest.json` |

## zip 与 .user.js 的结构

**扩展包**：打包时 `cd extension` 再 `zip .`，所以 zip 根目录直接是 `manifest.json`：

```
chaoxing-auto-helper.zip
├── manifest.json      ← 根层
├── icons/
└── src/
```

用户解压后能直接选这个目录加载，不用再进一层。

这也是为什么**不要**用「下载源码 zip」的方式分发 —— GitHub 的源码 zip 会套一层 `chaoxing-auto-helper-main/`，里面还有 `extension/`，用户很容易选错层级。

**油猴脚本**：单文件，`userscript/学习通自动学习助手.user.js`。Tampermonkey 打开即装，无需解压。

## 排查构建失败

```
仓库页 → Actions → 点进失败的那次 → 展开红色步骤
```

常见问题：

| 现象 | 原因 |
|---|---|
| `找不到 extension/manifest.json` | 目录结构被改了 |
| `引用的文件不存在: xxx` | manifest 里写了但文件没提交 |
| `xxx 语法错误` | JS 有语法问题 |
| `zip 结构不对` | 打包命令被改动 |
| `产物缺少 UserScript 头` | 构建脚本的 header 模板被改坏 |
| `版本不一致：产物 x / manifest y` | 手动改了产物文件（产物是构建出来的，别手改） |
| `产物里残留 chrome.* 调用` | 有人在逻辑层直接调了扩展 API，脚本版会失效 |

本地可以先自查一遍：

```bash
# 构建 + 5 项校验（最快发现问题）
node build/build-userscript.cjs

# 扩展语法与引用
node tests/core.test.cjs
node tests/test-build.cjs
node tests/test-options-theme.cjs
```

## 回滚发布

Release 里的包已经发出去了，撤不回来。但可以：

**打补丁版**（推荐）

```bash
# 改版本号 1.0.2，修好问题，重新发
git tag -a v1.0.2 -m "v1.0.2 修复 xxx"
git push origin v1.0.2
```

**删除错误的 Release**

```
Releases → 点进那个版本 → Delete
```

对应的 tag 也要删：

```bash
git push --delete origin v1.0.1
git tag -d v1.0.1
```

## 关于 Chrome Web Store

如果以后想上架商店，这个 zip **不能直接提交** —— 商店要求：

- 单独的隐私政策页面（说明不收集数据）
- 更详细的商店描述和截图
- 可能需要调整权限说明

`<all_urls>` 权限在审核时会被重点问，需要准备好解释（截图解题需要访问任意页面）。

个人用的话，Release 下载 + 加载解压缩的扩展就够了。
