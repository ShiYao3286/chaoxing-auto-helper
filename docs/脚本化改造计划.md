# 脚本化改造计划：一份内核 → 两种形态

> **目标**：把现有扩展的刷课/答题能力抽成**宿主无关的内核**，同一份源码产出两个产物：
> ① **Edge 扩展**（主形态，解压加载即用，能力不减）② **油猴用户脚本 `.user.js`**（单文件，装 Tampermonkey 即用）。
> **范围**：刷课 + 答题**全保留**（任务队列、任务点判定、路由代际、提交安全网、视频弹题）。
> **UI**：结构借鉴搜题酱的设计语言，配色/渐变/语义色自有（§3.4）。
> **制定时间**：2026-10-21　**基线版本**：v1.3.0（182 项测试全过）
> **状态**：✅ **已全部实施完成**（8 个阶段全过，测试从 182 增至 381 项）

**样张**：`docs/images/ui-adopted.png`（悬浮面板 + 设置弹窗 + 令牌表）

## 一、先说结论

**不要再写第二套代码。** 把「只有扩展能做」的部分收敛成一个薄薄的**宿主适配层**（约 200 行），
其余 4000 行刷课/答题逻辑原样复用。这样：

- 扩展侧只动 **14 个调用点**，风险极小，182 项测试兜底；
- 脚本侧靠**构建脚本拼接**产出单文件，不维护第二份逻辑；
- 以后加功能只改内核，两个形态同时受益。

> 一句话：**内核写一遍，宿主各写一小撮，构建脚本拼一次。**

## 三、核心设计

```
                  ┌─────────────────────────────┐
                  │   core/  内核（零 chrome）    │
                  │   config  prompt  api        │
                  └──────────────┬──────────────┘
                                 │
                  ┌──────────────┴──────────────┐
                  │  content/inject.js（存量）   │
                  │  队列 / 任务点 / 代际 / 安全网 │
                  │  只通过 Host.send 对外通信    │
                  └──────────────┬──────────────┘
                                 │ Host 接口（6 个方法）
              ┌──────────────────┴──────────────────┐
              ▼                                      ▼
   ┌───────────────────────┐            ┌────────────────────────┐
   │ host-extension.js     │            │ host-userscript.js     │
   │ chrome.runtime        │            │ GM_* + BroadcastChannel│
   │ + background.js       │            │ + localStorage         │
   └───────────┬───────────┘            └───────────┬────────────┘
               ▼                                    ▼
        Edge 扩展（主）                     油猴脚本（单文件）
```

### 3.1 宿主接口（6 个方法 + 1 个回调）

| 方法 | 语义 | 扩展实现 | 脚本实现 |
|---|---|---|---|
| `Host.getCfg()` | 读配置 | `chrome.storage.local` | `GM_getValue('cs.cfg')` |
| `Host.setCfg(patch)` | 写配置 | storage + 广播 | `GM_setValue` + 总线广播 |
| `Host.getRunning()` / `setRunning(v)` | 运行态 | storage + `tabs.sendMessage` 广播 | GM 存储 + 总线广播 |
| `Host.send(type, payload)` | 通用消息（答题/视觉/字体/截图/busy） | `chrome.runtime.sendMessage` | 本地分发到 `core/api` + 总线 |
| `Host.onMessage(fn)` | 接收广播 | `chrome.runtime.onMessage` | 总线订阅 |
| `Host.openOptions()` | 打开设置 | `openOptionsPage()` | 打开脚本内置设置弹窗 |
| `Host.reportStatus(s)` / `reportDetail(d)` | 心跳上报 | `frame:status` / `frame:taskdetail` | 总线广播 |

> 设计要点：`Host.send` 保持「`type` 字符串 + `payload` 对象 + 返回 Promise」的**消息形状不变**，
> 这样 `inject.js` 的 14 处改动就是纯粹的函数名替换，逻辑零改动。

### 3.2 跨帧总线（脚本版最大难点）

扩展靠 background 的共享内存做跨帧协调（`frame:status` 汇总 → `tab:busy` 判断）。
油猴脚本没有后台，但有**同源 iframe**，所以：

| 步骤 | 做法 |
|---|---|
| ① 拿 tabId | 顶层生成 uuid 写入 `<html data-cs-tabid>`；子帧读 `window.top.document.documentElement.dataset.csTabid`（同源可读，且 DOM 跨世界共享） |
| ② 建通道 | `BroadcastChannel('cs-bus-' + tabId)`；没有则退回 `localStorage` + `storage` 事件 |
| ③ 上报 | 每个帧把 `{frameKey, status, busy, detail, ts}` 广播出去 |
| ④ 查询 | 顶层本地维护 `Map<frameKey, status>`，`tab:busy` = 排除自己后是否有人 `busy` 且 `ts` 在 8 秒内 |

`frameKey`：脚本里拿不到 `frameId`，用「顶层到自己的 iframe 序号链」生成稳定 key
（`window.top.document.querySelectorAll('iframe')` 里逐层定位；失败则用随机 uuid + 心跳续期）。

**风险**：`window.top.document` 若跨域会抛错 → 退回「单帧模式」（各帧独立判断，不做全局 busy 互斥）。
这种情况扩展也是一样的限制，属于已知退化。

### 3.4 UI 方案：结构借鉴搜题酱，配色自有

> 已确认采用。样张：`docs/images/ui-adopted.html` / `.png`（可直接浏览器打开看）
> 对照：`docs/images/ui-style-compare.html` / `.png`（旧版 vs 搜题酱 vs 令牌）

**结论**：**采用搜题酱的「设计语言」，但不复用它的任何代码/图标资产，并且换掉主色与渐变。**

| 维度 | 沿用（通用设计参数，不受版权保护） | 改成自有（保持识别度） |
|---|---|---|
| 卡片 | 白底 + **12px** 圆角 + 柔和阴影 | 阴影改 `0 8px 24px rgba(15,23,42,.10)` |
| 布局 | **左标签 · 右控件**，行高 14px | 行距 13px，标签列 104px（设置页） |
| 控件 | **Element 风格开关 40×24**（开源组件） | 关态色 `#dcdfe6`，开态用我们主色 |
| 按钮 | **32px 高**、圆角 8px、白底细边 | **带图标**：`▶ 开始` / `■ 停止`（它纯文字） |
| 面板宽 | **300px**（与我们现在一致） | 不改 |
| 标题 | 16px / 600 / **渐变文字**（`background-clip:text`） | 渐变端点与角度换掉（见下） |
| 主色 | — | **`#2d6cdf`**（它 `#2655fe`） |
| 渐变 | — | **`linear-gradient(135deg, #4b8bf5, #2d6cdf)`**（它 `270deg, #009bfb → #2655fe`） |
| 语义色 | — | **保留我们的绿橙灰**：完成 `#2da44e`、进行中 `#b26a00`、跳过 `#8b949e`（它整个面板只用蓝） |

**为什么语义色不跟它**：搜题酱整个面板一个蓝色系打天下，扫一眼分不出"做完了还是正在做"。
我们的队列行用绿 ✓ / 橙 ⚠ / 灰划线，**一屏就能看清进度** —— 这是现有实现的优势，不能为了像而丢掉。

**法律边界（写进文档，实施时守）**：

| 可以 | 不可以 |
|---|---|
| 颜色值、圆角、间距、字号、渐变参数 | 复制它的 `SideBar.45e5288b.css` 代码 |
| Element-UI 开源控件（MIT） | 复用它的 88 个 PNG/SVG 图标资产 |
| 通用交互模式（左标签右控件） | 照搬它的 Vue scoped 类名（`.brush-course-panel[data-v-xxx]`） |
| 参考它的信息层级与节奏 | 把面板做成像素级一模一样（易被认作抄袭） |

> **为什么内核用 IIFE 挂全局而不是 ESM**：MV3 content script 必须是经典脚本，
> 而 background 的 `importScripts()` 也是经典。一套「挂 `root.CSCore`」两边通吃，无需打包器。

### 4.2 构建脚本做什么

```
build/build-userscript.cjs：
  1. 读 userscript header 模板（@match/@grant/@connect/@version）
  2. @version 从 extension/manifest.json 读，保证版本一致
  3. 按顺序拼接：
     header → core/*.js → host-userscript.js → ui/theme.js
            → ui/panel.js → ui/settings.js → content/fontdecoder.js → content/inject.js
  4. 校验（不通过就 fail，防止漂移）：
     - 拼接结果里除 host-userscript.js 外不得出现 chrome.
     - 必须含 @match 两条（chaoxing / edu.cn）、@grant GM_xmlhttpRequest / GM_setValue 等
     - ui/*.js 里不得出现硬编码颜色（必须走 CSTheme）—— 用正则查 # 六位色值
     - 单个文件大小报告（提醒是否过大）
     - node --check 语法检查
  5. 写入 userscript/学习通自动学习助手.user.js
```

**构建只服务脚本版；扩展不需要构建**（`extension/` 目录直接加载，manifest 里多列几个 js 即可）。
这是刻意的：扩展"下载解压就能装"的体验不能被引入构建步骤破坏。

## 六、风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | 阶段 1 重构把扩展搞坏 | 高（主形态不可用） | 纯机械替换；改完立刻跑 182 项；任何回归就回滚该步 |
| 2 | 脚本版跨帧总线不可靠 | 中（可能多帧抢跑） | 优先级：BroadcastChannel → localStorage → 单帧模式；每级都有降级 |
| 3 | 脚本拿不到真实截图 | 中（视觉解题精度降） | 已有 `renderTextToImage` 兜底；README + 设置页明示；阶段 6 可选 foreignObject |
| 4 | 油猴 `@connect *` 让用户困惑 | 低 | 文档写清：首次调 API 会弹授权，必须点允许 |
| 5 | 脚本更容易被识别为自动化 | 中（风控） | 复用现有风控检测（识别到就停）；提供「隐藏注入标记」开关（不写 `data-cs-booted`） |
| 6 | `about:blank` 内层 iframe 脚本可能不注入 | 低 | 扩展有 `match_about_blank`；脚本靠 `@match` 命中最终 URL；无法覆盖时退化为标签逻辑 |
| 7 | 双形态长期漂移 | 中（维护性） | 构建脚本内置校验：非 host 文件出现 `chrome.` 就 fail；测试双形态各跑一遍 |
| 8 | 两个形态配置不同步 | 低 | 明确分开存储，文档说明"互不相通" |
| 9 | **UI 换皮引入视觉回归** | 中（面板坏掉/难用） | 3.2 只搬不改 DOM id；面板测试 9 项必须全过；`ui-adopted.png` 存为视觉基线 |
| 10 | **UI 被认作抄袭搜题酱** | 中（社区口碑） | 主色/渐变/语义色/按钮图标全部自有；不复用其 CSS/图标/类名；文档记录边界 |
